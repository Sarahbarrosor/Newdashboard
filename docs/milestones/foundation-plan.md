## Stack (confirmed)

- Vercel Postgres (Neon) via `@vercel/postgres`

No pnpm monorepo — single Next.js app for simpler Vercel deploy.

## Database schema

Single migration `drizzle/0000_init.sql` auto-generated from `lib/db/schema.ts`:

- `users` (id, email unique, passwordHash, name, role, countryCode, createdAt)
- `locations` (id, code unique, name, city, currency, createdAt)
- `products` (id, sku unique, name, category, unit, cells, lastSynced, timestamps)
- `stockLevels` (id, productId, locationId, qtyOnHand, threshold, lastSynced; unique(productId, locationId))
- `transfers` (id, referenceCode unique, fromLocationId, toLocationId, productId, qty, status, urgent, note, createdBy, approvedBy, receivedBy, timestamps)
- `activityLog` (id, eventType, tone, countryCode, actorId, subjectType, subjectId, text, payload jsonb, createdAt)

Enums: `user_role` (`global_admin | country_admin | viewer`), `transfer_status` (`pending | transit | received | cancelled`), `country_code` (`US | MX | CO | AR | ES`).

## Access control

Without Supabase RLS, authorization is enforced in route handlers / server actions via `lib/auth/helpers.ts`:
- **Reads** — all authenticated users can read any country's data (matches the "country admins have read access to ALL" invariant).
- **Writes** — every write path starts with `await requireCountryWrite(targetCountry)`. Global admin bypasses the country check.
- Helpers throw typed errors that surface as 403 in route handlers and `throw redirect('/unauthorized')` in server components.

This is tested in Transfer and Dashboard milestones. Foundation only needs the helpers in place.

## Deploy flow (codified in `DEPLOY.md`)

1. Vercel → Import `sarahbarrosor/newdashboard`.
2. Storage → Create Postgres (nearest region). Connect to project — env vars auto-populate.
3. Add env vars: `NEXTAUTH_SECRET` (generated), `NEXTAUTH_URL` (Vercel URL).
4. Deploy. Migrations run via `prebuild` script (`drizzle-kit migrate`). Seed is run manually once via `vercel env pull && pnpm seed` from a throwaway local checkout — instructions in DEPLOY.md.
5. Log in at `/login`.
